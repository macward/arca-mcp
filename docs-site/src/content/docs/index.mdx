## Qué resuelve

ARCA/AFIP expone servicios SOAP históricos, errores opacos y una separación estricta
entre homologación y producción. **arca-mcp** los envuelve en herramientas MCP
deterministas: inputs estructurados, outputs estructurados, sin heurísticas fiscales
ocultas — pensadas para que un LLM (o tu código) las use sin equivocarse.

<CardGrid stagger>
  <Card title="Determinista" icon="setting">
    Cada tool recibe inputs validados con Pydantic y retorna estructuras predecibles.
    Los errores opacos de ARCA se traducen a `{ cause, message }` legibles.
  </Card>
  <Card title="Human in the Loop" icon="approve-check">
    Las acciones irreversibles siguen `create_voucher_draft → validate_voucher_draft →
    confirm_voucher_creation`. Nunca se emite sin confirmación explícita.
  </Card>
  <Card title="Seguro por diseño" icon="seti:lock">
    La private key nunca se expone al LLM. La firma CMS y el login WSAA ocurren
    localmente. Homologación y producción están estrictamente separadas.
  </Card>
  <Card title="Idempotente" icon="random">
    Toda emisión recibe un `idempotency_key`. El estado se persiste en SQLite con
    write-ahead-log para sobrevivir crashes y evitar doble facturación.
  </Card>
</CardGrid>
